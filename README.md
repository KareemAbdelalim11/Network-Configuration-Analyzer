# VLAN Risk Platform

A Python-based network auditing and risk-analysis tool for VLAN-aware network environments. It analyzes Cisco-style configuration files, identifies potential VLAN and switching risks, models network topology, and exports reports to help administrators review findings before making changes.

## Features

- **Device discovery and configuration parsing** for network device configuration files.
- **VLAN and switching checks**, including VLAN consistency, trunk configuration, native VLANs, SVI configuration, gateway consistency, and duplicate gateways.
- **Network risk scoring** with detected issues and severity indicators.
- **Topology generation** and visualization.
- **Connectivity-impact prediction** for detected issues.
- **Spanning Tree Protocol (STP) simulation**.
- **Connectivity tests** and recovery/rollback recommendations.
- **HTML report export**.
- **Streamlit dashboard** for uploading configuration files and reviewing analysis results.

> This tool is an analysis aid. Validate findings against the live network and your organization's change-management process before applying any configuration changes.

## Project structure

```text

├── analyzers/             # VLAN, trunk, gateway, SVI, risk and rollback checks

```

## Requirements

- Python 3.9 or newer recommended.
- `pip`
- Dependencies listed in `requirements.txt`.

The dashboard uses Streamlit. Other dependencies support data handling, topology visualization, and YAML parsing.

## Installation

1. Clone or download this repository and enter its directory:

   ```bash
   git clone https://github.com/KareemAbdelalim11/Network-Configuration-Analyzer.git
   cd vlan-risk-platform
   ```

2. Create a virtual environment:

   **Windows (PowerShell):**
   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

   **Linux/macOS:**
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

3. Install the dependencies:

   ```bash
   python -m pip install --upgrade pip
   pip install -r requirements.txt
   ```

## Usage

### Option 1: Web dashboard

From the project root, run:

```bash
streamlit run ui/dashboard.py
```

Open the local URL printed by Streamlit in your browser. Upload one or more supported Cisco configuration `.txt` files, then select **Analyze Network**. Review the risk score, device summary, detected issues, and generated reports.

### Option 2: Command-line analysis

From the project root, run:

```bash
python main.py
```

The command-line entry point discovers configuration files from the locations supported by the project code, performs the analysis, and prints a summary. The sample configurations are in `configs/`; check the discovery logic in `core/device_discovery.py` if you need to confirm which directory is read by your current version.

## Outputs

Depending on the selected workflow, the project can produce:

- An overall network risk score (0–100).
- A list of detected issues and severity levels.
- A discovered-device summary.
- Connectivity test results and predicted connectivity impacts.
- STP simulation events.
- Recovery or rollback recommendations.
- An HTML report at `reports/report.html`.
- A topology graph at `reports/topology.png` (when generated by the current workflow).
- Runtime logs under `reports/`.

Generated outputs may be overwritten by later runs. Save copies of any reports you need to retain.

## Input files

The dashboard accepts `.txt` configuration files. For best results:

- Use text exports of the relevant network-device configurations.
- Remove passwords, shared secrets, SNMP communities, private keys, public IPs, and other sensitive values before uploading or sharing files.
- Use clear filenames that identify each device.
- Test with sanitized sample configurations before using operational network data.

The repository includes example files under `configs/`. Review their contents before using them as a basis for your own environment.

## Safety and limitations

- The platform analyzes configuration text and simulated topology; it should not be treated as a substitute for vendor tooling or a live-network validation process.
- Findings depend on the completeness and format of the input configurations and the checks implemented in this version.
- Connectivity and STP results may be simulated or inferred rather than measured from live equipment.
- Review all generated rollback/recovery recommendations before using them. Do not automatically apply suggested changes to production devices without testing and approval.
- Do not commit credentials, customer configuration files, or sensitive network information.

## Troubleshooting

- **Missing dependency:** activate the intended virtual environment and run `pip install -r requirements.txt`.
- **Dashboard import errors:** run Streamlit from the project root so imports such as `core` and `topology` resolve correctly.
- **No devices found:** check the input directory expected by `core/device_discovery.py`, confirm the files are plain text, and verify that their format is supported.
- **No report or graph appears:** check the terminal output and the `reports/` directory for errors and generated artifacts.
